Local installer plugins.

Add a manager or setup helper that is not in the built-in registry using a YAML manifest and an optional local script.

DOCUMENTATION
OverviewGetting startedManager guideLocal pluginsSafety & privacy

1. Create the plugin directory

By default, put a YAML manifest and any script in ~/.app_store_store/plugins/. On Windows the default is %USERPROFILE%\.app_store_store\plugins\. Override the location with APP_STORE_PLUGINS or --plugins-dir PATH.

Manifest files must end in .yaml or .yml. A script must use a relative path and stay inside the plugin directory.

2. Add a manifest and script

This example defines a Windows-only PowerShell plugin. Save it as example-manager.yml and place install.ps1 next to it:

id: example-manager
name: Example Manager
os: windows
description: Example package manager installed by a local script.
homepage: https://example.org/
install_page: https://example.org/install
installer_type: powershell
plugin_script: install.ps1
installed_check: [example-manager]
requires: [powershell]

Allowed local script types are .sh with bash, .ps1 with powershell, and .py with python. The script must exist and have an extension matching the declared type.

3. Configure operating-system profiles

For an installer downloaded from an official HTTPS location, specify its URL, local filename, and runner instead of plugin_script:

installer_url: https://example.org/install.sh
installer_file: install.sh
installer_type: bash

For platform-specific installers, use an installers list. Each profile has an os value or list. An optional arch list limits a profile to Rust architecture names such as x86_64 or aarch64.

installers:
  - os: [linux, darwin]
    installer_url: https://example.org/install.sh
    installer_file: install.sh
    installer_type: bash
  - os: windows
    installer_url: https://example.org/install.ps1
    installer_file: install.ps1
    installer_type: powershell

Supported downloaded installer types include Bash, PowerShell, Python, PHP, and executable installers. Command profiles run an already-installed executable with fixed arguments and declared prerequisites; see the existing registry for examples.

4. Validate and use it

Run the app and confirm the manager appears on the OS you declared:

cargo run -- --list
cargo run -- --plugins-dir PATH --list

Select a local script entry in the GUI or TUI to run it after confirmation. A downloaded installer must be downloaded before it can be run. A plugin that only supplies an official setup page should instead use that link in the built-in registry; plugin manifests must provide a script or installer.

Important plugin safety

Plugin scripts are not sandboxed. They run as your user and may change files, install software, or invoke other commands. Use only scripts you wrote or reviewed and trust. Confirmation is a prompt—not a security boundary.

Script path canonicalization prevents a plugin manifest from pointing outside the configured plugin directory. It does not make the script itself safe.

For more, read Safety & privacy.
